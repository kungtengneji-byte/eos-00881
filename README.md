# 00881 EOS 每日追蹤平台

兩個每日自動追蹤的模型，共用同一套收集、計分與發布管線：

| 標的 | 模型 | 頁面 |
|---|---|---|
| **00881** 國泰台灣科技龍頭 ETF | Entry Opportunity Score（EOS），六構面 | `index.html` |
| **TWMARKET** 台股大盤資金流向 | 外資續買燈號，七因子 | `market.html` |

每交易日自動收集資料、計分，並提供手機可瀏覽的歷史介面。兩頁互相連結。

> **這不是投資建議。** EOS 是規則型研究分數，不是上漲機率 ——
> 80 分不代表「80% 會漲」。任何分數、訊號或統計結果都不構成投資建議、
> 報酬保證或價格承諾。

## 模型

EOS = 0.15A + 0.25B + 0.20C + 0.15D + 0.15E + 0.10F，滿分 100。

| 構面 | 權重 | 內容 |
|---|---:|---|
| A | 15 | ETF 折溢價（市價相對淨值） |
| B | 25 | 含息趨勢、回檔、RSI14、實現波動率 |
| C | 20 | Top10 成分股廣度與加權貢獻 |
| D | 15 | 海外科技（SOX、Nasdaq、TSM ADR、NVDA） |
| E | 15 | 風險環境（VIX、US10Y、USD/TWD） |
| F | 10 | 量價與法人資金流 |

評分門檻定義在 [`eos_rubric_v1.1.yaml`](eos_rubric_v1.1.yaml)。

### 外資續買燈號（TWMARKET）

滿分 100，七個因子各自線性正規化後夾在 0–1 再乘權重，逐項對齊原工作表的
〈模型與定義〉分頁。

| 因子 | 權重 | 內容 |
|---|---:|---|
| F1 | 15 | 本波連買天數餘裕（相對視窗內最長買波） |
| F2 | 15 | 本波累計規模餘裕（相對視窗內最大買波） |
| F3 | 20 | 外資期貨未平倉 5 日回補 |
| F4 | 15 | 距前高壓力空間 |
| F5 | 10 | 融資 2 日變化（反向） |
| F6 | 15 | 前一美股時段費半 |
| F7 | 10 | 美 10 年期公債殖利率 |

評級 ≥65 續買動能明確／45–64 可續買但進入賣壓測試區／<45 賣壓風險升高。

F4 的分母是視窗內**最高盤中價**（工作表的壓力2），不是最高收盤。
兩者差很多：2026-09-18 用盤中高是 0.84%（F4 得 4.2 分），用最高收盤只有
0.31%（1.5 分）。盤中高永遠 ≥ 最高收盤，用收盤會系統性低估壓力空間 ——
改正後 35 天裡 22 天分數上升、0 天下降，平均 +2.6 分。
盤中高缺值時 F4 直接不計分，不退回用收盤。
門檻定義在 [`market_rubric_v1.0.yaml`](market_rubric_v1.0.yaml)，
視窗為固定回看 60 個交易日。

大盤每天同時產出兩個分數：**當日燈號**用台股當天對應的美股時段（T−1），
**明日展望**改用最新一場已收完的美股，其餘六項輸入相同 ——
兩者的差距就是隔夜美股帶來的變化。原工作表是隔天早上建立的前瞻訊號，
平台算的是回顧值，兩者都出才不會把兩種東西混為一談。

### 壓力與支撐

對齊工作表〈外資波段與壓力點〉，由高到低排成一把尺，最新收盤插在它該在的位置：

| 點位 | 規則 |
|---|---|
| 壓力2 | 視窗內最高盤中價 |
| 壓力1 | 次高盤中價（與壓力2 構成前高壓力帶） |
| 壓力區下緣 | 期間最高收盤與前波外資成本取高者 |
| 前波外資成本 | 最近一段買波，以每日買超金額為權重的指數加權平均 |
| 支撐1…N　壓力轉支撐 | 被收盤站上的前一日盤中高（回檔第一個測的位置） |
| 支撐1…N　波段低點 | 前後各 2 日皆不低於它的轉折低 |
| 外資轉買首日收盤 | 最近一段買波的起始日收盤 |
| 期間最低收盤 | 視窗內最低收盤 |

每一列都標出成因：**K線**（純由開高低收推出）、**資金**（由外資買賣超推出）、
**區間**（視窗端點）。壓力轉支撐與波段低點各取最近兩個再合併排序 ——
全部倒在一起排的話，密集的壓力轉支撐會把波段低點整個擠掉。

以工作表的 2026-09-18 版本逐項核對，五個可機械重現的點位全部到分：
壓力2 47,578.24、壓力1 47,548.26、壓力區下緣 47,326.27、
前波外資成本 47,049.35、支撐3 45,511.49。波段切分是平台自己跑的，
算出的「前波」正好是工作表的 9/4–9/9。

工作表「支撐1」46,874.84 也重現了，但成因不是它寫的「跳空缺口上緣概念」——
09-18 開盤 46,449.56 低於 09-17 最高，那天並沒有跳空。真正成立的是
**壓力轉支撐**：09-18 收盤 47,180.75 站上 09-17 的盤中高 46,874.84。
數值對、標籤錯，測試把這件事釘住了。

盤中高低來自 TWSE `MI_5MINS_HIST`（FMTQIK 只有收盤）。兩支端點的收盤在
2026-08/09 共 31 個交易日完全一致，測試會持續檢查這件事 ——
任何一天對不起來都代表其中一支改了口徑，那時混用會算出錯誤的壓力點。

### 連續買賣超 Top5

同一類法人（外資／投信／自營商／三大法人）連續同方向買或賣的天數排行，
資料來自 TWSE T86 全市場逐檔法人買賣超。TWSE 不提供任何「已連續幾天」的欄位，
因此平台自己保留逐日檔（`data/stocks/`，每天約 33KB）再回頭數。

當日淨額為 0 視為中斷 —— 與波段切分同一條規則，0 沒有方向。
連到視窗最舊一天者標記為截斷（顯示「≥」），實際天數可能更長。

計分式與參數取自工作表左上角的藍字可調區：

```
分數 = 天數 × 天數權重 + 狀態加分 + 兩類以上法人同向加分 + 天數/100
連續門檻 3 日／天數權重 1／持續中 +10／待確認 +5／兩類以上同向 +3
```

最後那一項工作表的規則沒有寫出來，但七筆實例裡有六筆只有加上它才對得起來
（第一金 28.16、聯電 24.11、兆豐金 19.12、台新新光金 18.18、中華電 18.13、
華邦電 8.05），它是同分時的排序尾數。參數全部在
`config/instruments/TWMARKET.yaml` 的 `streaks` 區塊。

狀態：**持續中**（連到最新資料日）／**待確認**（最新日該檔無任何法人紀錄，
無從確認是否延續）／**已中斷**（最新日有紀錄但轉向或歸零）。
已中斷的連續仍然上榜 —— 工作表的連買第一名（第一金）早在四天前就中斷了，
一段剛結束的長連買本身就是資訊，該由狀態欄說明，不是從榜上刪掉。

「主導法人」是每一檔取分數最高的那一類法人再跨檔排名，對應工作表的主表；
另有外資／投信／自營商／三大法人四個單一法人別的分頁。
約當金額＝張數 × 1,000 × 當日收盤 / 1e8（實測聯電 100,630 張 × 141.50 = 142.39 億）。

### 不繞過機器人驗證

Stooq 與臺灣銀行牌告匯率在 2026-09 分別加上了 JavaScript proof-of-work 與
Imperva challenge。本專案**不繞過**這類機制，兩者皆已剔除並改用替代來源。
`sources/base.py` 會偵測驗證頁並把該欄位標為 `UNAVAILABLE`，而不是靜默失敗。

## 資料品質原則

每個欄位都帶 `{value, source, url, as_of, status}`，`status` 為
`ok` / `missing` / `stale` / `conflict` / `unavailable`。

**缺值絕不以推估值或鄰近日期代算。** 例如當日正式 NAV 尚未發布時，
折溢價就是 `missing`，不會拿前一日 NAV 頂替。

依覆蓋率分級發布：

| 可計分構面 | 行為 |
|---|---|
| ≥ 90 | 發布「確定」分數 |
| 70–89 | 發布「暫定」分數，回補後升級 |
| < 70 | 不計算 EOS，只顯示已取得的分項 |

這個門檻是實測得出的：覆蓋率 ≥96% 的三天與人工判讀誤差為 0 / −2 / +5，
覆蓋率 75–83% 的四天則擴大到 −12 ~ +16。

計分規則全部寫在 YAML，`eos/rubric.py` 只是解釋器 —— 調整門檻不需要改 Python。
8 個有人工判讀可對照的錨點日被鎖在 `tests/test_engine.py` 的回歸測試裡，
改動 rubric 就會失敗。資料齊全的兩天（9/3、9/24）誤差為 −2 與 **0**。

## 收集排程

| 窗 | 台灣時間 | 內容 |
|---|---|---|
| 窗 | 台北時間 | 內容 | 累計覆蓋率 |
|---|---|---|---:|
| W3 | 05:35 | 美股前一時段與風險指標 | 30（不出分） |
| W1 | 15:15 | 00881 收盤、三大法人、成分股 | 85（暫定） |
| W2 | 19:35（21:35 重試） | 正式 NAV、當日成分股權重 | 100（確定） |
| W4 | 隔日 09:05 | 回補過去 7 天所有缺值 | — |

大盤走同一套窗，內容不同：W1 收加權指數、三大法人、融資餘額、期貨未平倉
與全市場逐檔法人；W2 再抓一次期貨（定版較晚）；W3 收費半與美債。
兩個標的在同一個 job 裡依序跑，一個失敗不中止另一個。

由 `.github/workflows/collect.yml` 自動執行，結果直接 commit 回 repo，
Pages 隨之重新部署。**GitHub Actions 的排程不準時**，實際觸發常延遲
5–15 分鐘，偶爾會被跳過 —— W4 回補窗就是為此存在，單次漏跑不會造成永久缺口。

台股 T 日一律使用美股 **T−1** 的時段，避免用到台股收盤後才發生的資訊
（lookahead bias）。

## 手機介面

前端是零相依的靜態 PWA（`index.html` / `app.css` / `app.js` / `sw.js`），
圖表為手寫 SVG —— 不依賴任何 CDN，這個專案已經被 Stooq 與台銀的機器人驗證教訓過一次。

啟用方式：GitHub repo → Settings → Pages → Source 選 **Deploy from a branch**，
branch `main`、資料夾 `/ (root)`。網址為 `https://<帳號>.github.io/eos-00881/`，
手機開啟後可「加入主畫面」，離線時仍可讀取已快取的歷史。

Service Worker 對外殼採 cache-first、對 `data/` 採 network-first ——
顯示過期的 EOS 又看不出來，比多載一秒糟糕得多。

本機預覽：

```bash
python -m http.server 8811
```

## 執行

```bash
python collect.py --window w1                          # 00881 台股收盤窗
python collect.py --instrument TWMARKET --window w1    # 大盤
python collect.py --window all --date 2026-09-24
python collect.py --window w4                          # 回補過去 7 天的缺值
python -m scripts.show_snapshot 2026-09-24             # 某日每個欄位的值與來源
python -m scripts.rescore --instrument TWMARKET        # 只重算，不連外網
python -m scripts.backfill_stocks --days 60            # 回填逐檔法人（新上線時）
python -m scripts.backfill_taiex_ohlc                  # 回填大盤盤中高低
```

`rescore` 走的是收集器的同一個計分函式，不自己算一份 ——
大盤的波段推導、明日展望、與前一個「有發布分數」交易日的比較都在那裡。

每個部件（價格／法人／NAV／成分股／海外）獨立失敗，一個來源掛掉不會拖垮整天的收集；
所有部件皆為冪等，重跑同一個窗不會造成重複或損壞。

## 開發

```bash
pip install -r requirements.txt
pytest
```

測試完全以 `tests/fixtures/` 的真實 API 回應驅動，不連外網。
斷言刻意寫死已驗證的實際數值 —— 來源改版時應該立刻失敗，而不是
讓平台安靜地記錄錯誤資料。

每週排程的 `contracts` job 會對真實來源打一次，偵測來源腐化。
